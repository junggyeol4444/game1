### 광고 배치 5종

| 배치 | 보상 | 쿨다운 |
|---|---|---|
| `dailyDouble` | 오프라인 수익 2배 | 없음 (앱 시작 시 1회) |

## 2. 기획서에서 바꾼 것

### 2-0. (수정) 1차 구현이 기획안 2장을 정면으로 어겼다 — 목록 UI → 장면
첫 구현은 사업 탭이 "아이콘 + 이름 + 숫자 + 버튼" 목록이었다. 이건 기획안 2장이
**"순수 방치형은 숫자만 올려서 유저층이 좁다"**고 지목한 바로 그 형태이고,
9장의 광고 소재("빈 땅 → 도시 타임랩스")도 뽑을 수 없다. 참고작으로 적은
Idle Miner Tycoon은 갱도가 보이고 광부가 움직이는 게임이다.

→ UI 레이어를 전부 다시 만들었다. 게임 로직(economy/progression/밸런스)은 그대로다.
- 유닛 1개 = **움직이는 장면 밴드 1개** (`src/ui/scene/bands.ts`)
- 사업 탭 상단 = **사업장 전경** (`site.ts`)
- 도시 홈 = **자라는 도시 전경** (`city.ts`) — 홈 화면의 주인공
- 진행바 대신 장면 자체가 진행을 보여준다. 레벨이 오르면 화면 속 인력이 1→6명으로 늘어난다.
- 에셋 0개. 전부 캔버스에 코드로 그린다(1인 개발 · 용량 · 광고 소재 재활용).

### 2-1. 엔진: Unity → TypeScript + Capacitor
근거는 README 참고. 밸런스 데이터가 `src/data/` 에 순수 데이터로 분리되어 있어 Unity 이식 시 그대로 옮겨진다.

### 2-2. 탭 해금 시점을 뒤로 미룸
기획서에는 해금 순서만 있고 시점이 없었다. 시뮬레이터로 측정한 결과 초기 설계(도시 Lv.1/3/6/10/14)로는 **한 시간 안에 5탭이 전부 열려** 중기 루프가 사라졌다.
→ Lv.1 / 3 / 7 / 12 / 17 로 조정. 재개발은 Lv.20.

### 2-3. 자원 사슬을 "느슨한 병목"이 아니라 "가동률 하한"으로 구현
기획서 주의사항("사슬이 빡빡하면 스트레스")을 수치로 못박았다:
- 상위 자원이 0이어도 **최소 25% 가동** (설계도 강화로 최대 75%)
- 각 사업은 자원과 현금을 **동시에** 번다. 하위 탭이 자원을 먹어도 상위 탭 수입은 안 줄어든다
- 사슬은 도시 Lv.12부터 켜진다 (그 전까지 3탭 완전 독립)

즉 사슬은 "막는 장치"가 아니라 **"어느 탭을 키워야 하는지 알려주는 신호"**로 설계했다. 사업 탭 상단에 `가동률 62%` 로 항상 노출된다.

### 2-4. 저금통을 금액이 아니라 포인트로 채움
수입이 지수적으로 커지는 게임에서 "누적 금액"으로 채우면 진행률 표시가 무의미해진다.
→ 업그레이드 구매 +1 / 광고 +5 / 미션 +3 / 도시 레벨업 +20, 목표 300포인트.
보상은 개봉 시점의 초당 수입 8시간치로 환산. 도시 Lv.8 전에는 아예 노출되지 않는다.

## 3. 기획서 14장 미확정 항목 — 현재 선택

전부 바꿀 수 있다. 지금은 "1인 개발 1단계에서 가장 싼 선택"으로 잡혀 있다.

| 항목 | 현재 선택 | 이유 / 바꾸는 법 |
|---|---|---|
| 아트 스타일 | **코드로 그리는 2D 캔버스 장면** (`src/ui/scene/`) | 에셋 비용 0, 용량 0, 색·크기·인원이 전부 데이터라 밸런스에 따라 자동으로 변한다. 나중에 스프라이트로 갈아끼울 때도 그리기 함수만 교체하면 된다 |
| 카메라 | **사이드뷰 단면(side-view cross-section)** | 갱도·공장·사무실을 잘라서 보여주는 방식. 세로 화면에서 유닛을 위아래로 쌓기 좋고, Idle Miner Tycoon 이 검증한 구도 |
| 타겟 지역 | **국내 소프트런칭 우선** | 매니저 이름·문구가 전부 한국어. 글로벌은 i18n 추출 후 (README 참고) |
| 도시 테마 | **현대 한국 도시** | 매니저 30명 이름, 사업 명칭이 현대 한국 기준 |
| 1단계 프로토타입 탭 | **광산** (기획서대로) | 사이클 0.8초로 가장 짧아 튜토리얼에 적합 |

## 4. 밸런스 구조 (재현 가능하게 남김)

`npm run sim -- --days 21` 로 언제든 재측정 가능하다.

핵심 수식:
- 유닛 가격: `baseCost × costScale × costGrowth^level` (growth 1.07~1.15)
- 유닛 산출: `baseOutput × outScale × level × 마일스톤 × 사업배율`
- 회수 기간: `payback = 3.2 × costScale / outScale` 초
- 도시 레벨 요구 누적 세수: `60 × (4.2^(L-1) − 1) / 3.2`
- 재개발 설계도: `80 × √(이번 회차 누적수익 / 1e14)`

사업별 회수 기간 (뒤로 갈수록 길다 = 새 탭이 기존 탭을 즉시 무의미하게 만들지 않는다):

| 사업 | 해금 | payback |
|---|---|---|
| 광산 | Lv.1 | 3.2초 |
| 공장 | Lv.3 | 19초 |
| 어항 | Lv.7 | 115초 |
| 놀이공원 | Lv.12 | 691초 |
| 기업 | Lv.17 | 4160초 |

> 이 비율을 건드릴 때는 반드시 시뮬레이터를 다시 돌릴 것. 초기 설계는 payback이 전부 같아서
> 새 탭 해금 순간 수입이 250배 뛰었고, 도시 레벨 20개가 40분 만에 소모됐다.
