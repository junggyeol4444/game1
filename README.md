# 도시 키우기 : 방치형 시티

빈 땅에서 시작해 도시를 키우는 모바일 방치형 게임.
도시 안의 각 사업(광산 / 공장 / 어항 / 놀이공원 / 기업)이 독립된 방치형 탭이며, 자원 사슬로 연결된다.

기획안 v1(2026-08-18)의 코어 루프를 **플레이 가능한 상태로** 구현한 것이다.

---

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 (--host 로 같은 와이파이의 폰에서도 접속 가능)
npm run build      # 타입체크 + 프로덕션 빌드 -> dist/
npm run preview    # 빌드 결과 확인
npm run sim        # 밸런스 시뮬레이터 (npm run sim -- --days 30)
```

폰에서 테스트하려면 `npm run dev` 후 터미널에 찍히는 `http://<PC IP>:5173` 을 폰 브라우저로 연다.
홈 화면에 추가하면 PWA(전체화면)로 실행된다.

네이티브 앱(Android/iOS) 빌드는 [docs/NATIVE.md](docs/NATIVE.md) 참고.

---

## 왜 Unity가 아니라 웹인가

기획안 10장은 Unity를 잡았다. 이 구현은 TypeScript + Capacitor로 갔다. 이유:

- 이 게임의 코어는 숫자·UI 루프다. 3D 렌더링/물리가 없다.
- 1인 개발에서 가장 비싼 자원은 **반복 검증 속도**다. 웹은 링크 하나로 실기기 테스트가 되고, 빌드가 1초다.
- 광고/결제는 Capacitor 플러그인(AdMob, RevenueCat)으로 네이티브와 동일하게 붙는다.
- 밸런스 수식과 데이터는 `src/data/` 에 전부 분리해 두었으므로, 나중에 Unity로 옮기더라도 그대로 이식된다.

번들 크기는 gzip 19KB. 저사양 기기·신흥시장에서 유리하다.

## 게임 규칙 (구현된 것)

### 진행 축 3개
| 축 | 주기 | 내용 |
|---|---|---|
| 유닛 레벨 | 분 | 갱도/라인/어선/어트랙션/부서 레벨업. Lv.10/25/50/100/200/300/400에서 마일스톤 보너스 |
| 도시 레벨 | 시간~일 | 누적 세수(수익의 10%)로 상승. 사업 해금 + 스카이라인 성장 |
| 재개발 | 일~주 | 도시 리셋 → 설계도 획득 → 영구 강화 13종 |

### 자원 사슬
```
광산 ─원석→ 공장 ─제품→ 기업 ─매출→ 도시(세수)
어항 ─식재료→ 놀이공원 ─관광객→ 인구 ─노동력 배율→ 전 사업
```
- **도시 레벨 12 전까지는 사슬이 꺼져 있다.** 초반 3탭은 완전히 독립 작동한다.
- 상위 자원이 모자라면 가동률이 떨어지지만 **최소 25%는 항상 돌아간다**(설계도로 최대 75%까지 상향).
  스트레스가 아니라 "저기를 키워야 하는구나"라는 신호로 쓰기 위한 장치.
- 각 사업은 자원과 현금을 **동시에** 번다. 하위 탭이 자원을 소비해도 상위 탭의 수입은 줄지 않는다.

### 수익화 (스텁 구현)
- 광고 배치 5종: 복귀 2배(Daily Double), 탭 부스터 2배 2분, 임시 매니저 10분, 자금 보충, 재개발 +50%
- 인앱결제 5종: 스타터팩 / 저금통 / 사업 집중 부스터 / 광고 제거 / 재개발 가속
- 저금통은 도시 레벨 8부터 등장하고, 가득 차기 전까지 가격을 숨긴다
- **확률형 아이템(가챠) 없음** — 국내 확률 표시 의무 규제를 피하기 위한 의도적 설계

웹 빌드에서는 광고·결제 모두 스텁(가짜 오버레이 / 확인창)으로 동작하므로 루프 전체를 그대로 테스트할 수 있다.

### 접근성 (55세 이상 코호트 대응)
설정에서 글자 크기 3단계, 숫자 표기(축약/지수), 애니메이션 줄이기, 진동을 조절한다.
모든 터치 대상은 최소 38~44px, 기본 본문 15px.

## 밸런스 조정

숫자는 전부 `src/data/config.ts` 와 `src/data/businesses.ts` 에 있다.

```bash
npm run sim -- --days 21
```

탐욕적 구매 AI(초당 수익 증가 / 비용이 최대인 것부터 구매)로 진행 속도를 측정한다.
**실제 플레이어는 이 AI보다 2~3배 느리다**고 보면 된다.

현재 튜닝 기준(시뮬레이터 시간):

| 지점 | 시뮬 | 실플레이 추정 |
|---|---|---|
| 공장 해금 (도시 Lv.3) | 2분 | 4~6분 |
| 어항 해금 (Lv.7) | 8분 | 20분 |
| 놀이공원 해금 (Lv.12) | 33분 | 1.5시간 |
| 기업 해금 (Lv.17) | 2시간 | 5~7시간 |
| 첫 재개발 가능 (Lv.20) | 9시간 | 1~2일 |

사업 간 난이도 계단은 `costScale`(1레벨 가격)과 `outScale`(산출)의 비로 만든다.
`payback = 3.2 × costScale / outScale` 초. 뒤로 갈수록 회수 기간이 길어지도록 잡혀 있다
(광산 3.2초 → 기업 4160초). 이 비를 건드리면 "새 탭을 열자마자 기존 탭이 무의미해지는" 문제가 생기니 주의.

## 테스트

```bash
npm run build
npm run preview &
node tools/smoke.mjs http://localhost:4173/
```
Playwright로 실기기 해상도(390×844)에서 주요 화면을 눌러 보고 콘솔 에러를 잡는다.

디버그 콘솔:
```js
game.devGrant(1e12)          // 자금 지급
game.state.city.taxRun = 1e9 // 도시 레벨 밀어올리기
game.buyMode = 'max'
```
